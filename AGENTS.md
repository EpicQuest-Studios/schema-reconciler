# Schema Reconciler

Vendor-neutral, declarative, data-safe schema reconciler for Java (spec: `SPEC.md`).

## Modules

- `schema-reconciler-core` — API (`studio.epicquest.schema.reconciler`), model records, `Dialect` SPI, engine internals (`internal` package, not exported).
- `schema-reconciler-postgresql` — PostgreSQL 14+ reference dialect (`studio.epicquest.schema.reconciler.postgresql`, internals in `.internal`).
- `schema-reconciler-tck` — dialect conformance suite (`DialectConformanceTest`, C-01…C-67) for third-party dialects.

## Build

Java 25, Maven 3.9+. `mvn verify` builds all three modules and runs every test. Core and the PostgreSQL dialect are JPMS-modular; the TCK ships as an automatic module (`Automatic-Module-Name`).

## Tests

- Core: pure unit tests over an in-memory fake JDBC database (`FakeDb`) + `FakeDialect` — no real DB needed.
- PostgreSQL: needs a PostgreSQL 14+ database. Point tests at one via env vars:
  `RECONCILER_TEST_URL=jdbc:postgresql://localhost:55999/rcl RECONCILER_TEST_USER=rcl RECONCILER_TEST_PASSWORD=rcl mvn verify`
  Without env vars, `PgTestDatabase` falls back to a Testcontainers `postgres:18` container (requires Docker reachable by Testcontainers; with Docker Desktop on macOS `DOCKER_HOST=unix://$HOME/.docker/run/docker.sock` may be needed, or run a dedicated container: `docker run -d --name reconciler-tck -e POSTGRES_USER=rcl -e POSTGRES_PASSWORD=rcl -e POSTGRES_DB=rcl -p 55999:5432 postgres:18`).
- `DeploymentFixtureTest` migrates `src/test/resources/deployment/schema.sql` per spec A.7 at test time and reconciles it end to end.
- `CorpusFixtureTest` reconciles the obfuscated schema corpus `src/test/resources/corpus/corpus-*.sql` (same A.7 transform). corpus-01 declares `vector`/`pg_trgm` — on a plain `postgres:18` image it skips; full coverage needs `pgvector/pgvector:pg18` (or pg14/pg15/pg16/pg17/pg19 equivalents). Fixtures use the v18 `uuidv7()` builtin — `PgTestDatabase.ensureUuidv7` installs a pg_catalog stand-in on pre-18 servers — and v15 syntax (NULLS NOT DISTINCT, security_invoker) is downgraded by a test-only transform on pre-15 servers. Any new `corpus-NN.sql` file is picked up automatically.
- `AppendixCoverageTest` creates each construct of spec Appendix C's "detected but unsupported" list and checks its `OTHER` prefix; `CanonicalDefinitionTest` compares canonical definitions with the engine's `pg_get_*def` text. Both roll back; the transform and security-label cases need a superuser and are skipped otherwise.
- The PostgreSQL module's Surefire runs on the class path (`useModulePath=false`); main jars remain JPMS-modular.

## Releases

Artifacts are published as a Maven repository on the `gh-pages` branch (GitHub Pages) — anonymous HTTPS access, no credentials for consumers.

- Publish: `mvn -DskipTests deploy -DaltDeploymentRepository=pages::default::file:///<checkout-of-gh-pages>/maven`, then commit + push `gh-pages`.
- Delete a version or artifact: `git rm` it on `gh-pages` and push — removal takes effect immediately.
- Consumer repo URL: `https://epicquest-studios.github.io/schema-reconciler/maven`.

## Conventions

- No `CASCADE` in rendered drops; recreates are `DROP`+`CREATE` change pairs ordered two-phase over the dependency graph.
- `SchemaObject.attributes` carries dialect-private render fragments (`PgCatalog.CREATE_SQL` etc.) with `${namespace}` tokens, bound to the quoted target at render time.
- Canonical definitions normalize namespace refs to `${namespace}` (`PgSql.normalize`) so scratch and target snapshots compare equal.
- Policy order (spec 3.3): fail check (manual changes count APPLY as FAIL; each UNSUPPORTED difference resolves via `unsupportedCategories` → `unsupported`) → recreate pairing → prerequisite demotion closure; demoted changes record their blocker. Category key for `OTHER` ids is the name prefix before `:` (`privileges:`, `rule:`, `type:`…, spec A.5), else the lowercase kind name; non-managed relations carry relkind prefixes (`partindex:`, `inherited:`…) so tolerating one cannot exempt another.
- `apply(plan)` rejects a foreign-namespace/dialect plan before opening a connection; `verifyPlan` rechecks dialect id and fingerprint after resolve.
- `Dialect.checkAccess` runs once per session before the lock (PG: `to_regnamespace` must resolve, `has_schema_privilege` for `USAGE` and `CREATE` checked separately (a comma list means "any of"), plus `has_database_privilege CREATE` when the run will create the scratch namespace — `dump()` passes `createNamespace=false` and needs only the schema grants); `Builder.statementTimeout` is applied right after the lock as `SET LOCAL statement_timeout`, and again on the scratch connection when `scratchDataSource` is configured — bounds each statement (catalog reads included), never the lock wait or total run. Catalog getters (`pg_get_expr`) open the deparsed relation with `AccessShareLock` — inspection itself can block on a locked table.
- `PgCatalog` excludes extension-member objects (`pg_depend` `deptype='e'`) from every object loader — members can't be created/dropped standalone; the `pg_extension` row itself is a managed `EXTENSION` (`extension:<name>`, presence-only canonical). `CREATE EXTENSION` replay is confined to `SCHEMA <scratch>`; when the extension already exists elsewhere, `executeScript` relocates it into scratch under the savepoint so reruns stay convergent (an extension anchors to exactly one namespace globally).
- `PgScriptCheck` rejects what escapes the snapshot model or breaks transaction confinement — not what safely rolls back (3.2 rule 4: transactional effects, including foreign-table writes/locks/TRUNCATE/ANALYZE/CLUSTER/REFRESH, reindexing, NOTIFY/LISTEN/UNLISTEN, and CALLs of foreign routines, are confined to the scratch connection and stay legal). It rejects: qualified object names outside the scratch schema in CREATE/DROP/ALTER name position (incl. `ON`/`TO` targets of INDEX/TRIGGER/POLICY/RULE, comma-separated name lists, `ATTACH`/`DETACH PARTITION` operands, multi-word kinds like `TEXT SEARCH …`/`OPERATOR FAMILY|CLASS`, and qualifiers that are unreserved keywords such as `exists.evil` — the modifier-skip lands on `.` and the check backs up one token), plus qualified targets of GRANT/REVOKE/COMMENT/SECURITY LABEL (`pg_temp` allowed; `ON SCHEMA` grants/comments/labels rejected outright — the namespace is the reconcile unit itself; `ON ALL ... IN SCHEMA` schema lists bounded by the TO/FROM grantee clause), and, failing closed on statements whose catalog effect the snapshot cannot represent (3.2 rule 4): `TABLESPACE`/`REINDEX ... TABLESPACE` clauses, typed tables (`OF`, `NOT OF`), `CREATE TABLE ... USING` access methods, `CLUSTER ... USING`/`ALTER ... CLUSTER ON`/`SET WITHOUT CLUSTER`, `SET STATISTICS`, `RESTART`, `OWNER TO` on unmodeled-owner targets (incl. `ALTER INDEX`, a silent no-op), `ALTER INDEX ... ATTACH PARTITION`, `ALTER OPERATOR` forms beyond a class's `USING am ADD|DROP OPERATOR|FUNCTION` member mutations (standalone `OPERATOR FAMILY` members stay unmodeled), `ALTER TEXT SEARCH` forms beyond a configuration's `MAPPING` actions and a dictionary's `(opt = value, …)` option redefinition — both snapshot state, with `WITH`/`REPLACE` dictionary name lists still qualifier-checked — `DEPENDS ON EXTENSION`, collation `REFRESH VERSION`, and `ALTER VIEW ... SET|DROP DEFAULT`, `SELECT … INTO`/`IMPORT … INTO` (object creation; an `INTO` preceded by `INSERT`/`MERGE` is a write target, not creation), `TRANSFORM FOR`/`CAST (…)` anchors (the qualified type is the object's namespace anchor), and qualified literals in the first argument of `nextval`/`setval` in evaluating statements — they are non-transactional and survive the scratch rollback (the name-boundary match is verified through the call-gap: quoting and comments cannot evade it; every `'`/`$tag$` literal in the argument is parsed for a qualifier; the scan is gated on `evaluatesNow` so deferred bodies stay opaque), plus a string literal whose whole content is the substituted scratch name or carries the token text without a following `.` — a bare `${namespace}` inside a literal has no convergent target form (qualified `'${namespace}.seq'` forms stay legal). Foreign-schema names elsewhere (e.g. cross-schema `REFERENCES`, `INHERIT`/`PARTITION OF` parents, `FROM other.t` reads) stay legal. Session-state first-words `DECLARE`/`EXECUTE`/`DEALLOCATE`/`PREPARE`/`DISCARD`/`COPY`/`FETCH`/`MOVE`/`CLOSE`, session `SET`/`RESET`/`LOAD` (`SET LOCAL`/`TRANSACTION`/`CONSTRAINTS` allowed), and `CREATE`/`DROP`/`ALTER`/`REINDEX … CONCURRENTLY` forms are rejected per the PG docs' transaction-block rules — the same rules reject `CREATE/DROP DATABASE`/`TABLESPACE`, `ALTER SYSTEM`, bare `CLUSTER` (no table — `CLUSTER t` is confined and legal), bare/`CONCURRENTLY`/`USING INDEX`-only `REPACK` (PG19; `REPACK t` is confined and legal), and the `CONCURRENTLY` DDL forms, while `ALTER DATABASE`/`TABLESPACE`/`SUBSCRIPTION` are transaction-legal and rejected as database-wide objects (`REFRESH MATERIALIZED VIEW CONCURRENTLY` is legal). `ALTER DEFAULT PRIVILEGES` carves out like `ALTER PUBLICATION`: only the `IN SCHEMA`-scoped GRANT/REVOKE forms mutate the namespace-visible `pg_default_acl` row — the schema names must be the scratch namespace and a `GRANT`/`REVOKE` clause is required; a global default ACL is database-wide and rejected. `PgSql.statements` treats `BEGIN ATOMIC … END` routine bodies as opaque spans so their `;`s don't split the statement and `END` isn't misread as transaction control; routine bodies and rule actions are opaque to the check per spec §8 rule 5 — a callable COMMIT procedure is caught by the savepoint-intact backstop if the script invokes it. Functions whose effect isn't transactional — advisory session locks, `pg_terminate/cancel_backend`, replication slot/origin calls, WAL/backup/server control (`pg_switch_wal`, `pg_backup_start`, `pg_promote`, `pg_checkpoint`, `pg_reload_conf`, `pg_rotate_logfile`, `pg_log_emit`, `pg_logical_emit_message`), server file writes (`pg_file_*`, `lo_export`), statistics resets — are rejected, token-scan with a `(` call check so non-call identifier mentions stay legal (`pg_logical_slot_peek_*`, `pg_notify`, `lo_import`, `pg_advisory_xact_*` stay legal). Only `CREATE EXTENSION` is allowed (declares presence; its `SCHEMA` operand is checked) — `DROP`/`ALTER EXTENSION` mutate global state invisible to `extension:` tracking; `COMMENT`/`SECURITY LABEL ON EXTENSION` likewise. `DO` bodies execute during replay: `set_config` and `nextval`/`setval` are matched on the whole body text (with `''` escapes collapsed — spec §8 rule 5 scans literals deliberately), banned calls on the tokenized inner statements, plus the object-creation check for table-creating `INTO` forms — in PL/pgSQL `INTO` without a `TEMP`/`TEMPORARY`/`UNLOGGED`/`TABLE` lead-in is variable assignment (`rec.field` stays legal), the modifier-led forms create a table whose name is checked — and `EXECUTE '…'` literals inside them recurse through the full check. Every `set_config` call must pass the literal `true` third argument (parsed, not token-matched). A lock taken indirectly through a function the script invokes is released by `dropScratchNamespace` (`pg_advisory_unlock_all` after the savepoint rollback, which already undoes session settings).
- `PgRender` creates a table with `UNLOGGED`, `WITH (<reloptions>)` and `REPLICA IDENTITY FULL|NOTHING` (`PgCatalog.TABLE_OPTIONS`/`REPLIDENT`); `REPLICA IDENTITY USING INDEX` is the `POST_SQL` of the index or constraint, appended on every create/recreate.
- `PgRender` splits a drifted column by data risk: safe statements (`SET/DROP DEFAULT`, `DROP NOT NULL`, `SET STORAGE`, `SET COMPRESSION`, `TYPE` only for the widening allowlist: int chain, `varchar` growth/→`text`, `char` growth, `numeric` s′≥s∧p′−s′≥p−s) go in one `ALTER`-classified `REBUILD` change; `SET NOT NULL` gets its own `DESTRUCTIVE` change on the same column (fails on existing NULLs); generated/identity/collation and non-widening types stay manual `DESTRUCTIVE`. `char→varchar`/`text` is excluded — the cast strips trailing spaces.
- `SchemaReconciler.planTimed()` returns a `TimedPlan` (plan + `RunTimings`; `apply`/`verify` zero). `ReconcileReport.timings()` carries `RunTimings` (lockWait, readActual, loadDesired, plan, apply, verify) measured by `System.nanoTime`; failed runs surface timings on `SchemaReconcilerException.timings()` — completed phases plus the failed phase's partial duration, `ZERO` where nothing ran. The SPI `executeScript` takes the scratch namespace name for the qualified-name check.
- `PgCatalog.loadDependencies` covers: view→rel/proc/type (pg_rewrite), routine→rel/proc/type (aggregates and window functions register in `procByOid` too, so dependents of either resolve), index→proc, trigger→proc, constraint→proc/type/class/constraint (FK `conindid` resolves the referenced unique index to its backing constraint or the index object — `conindid` is only backing for `contype` `p`/`u`/`x`), column default→rel/proc/type (pg_attrdef — propagated to the parent table for covered columns, skipping owned-seq back-edges), column/table→type/collation (propagated up to the relation id — including `inherited:` OTHER relations and managed `PARTITION`/`FOREIGN_TABLE` children, so an unsupported or clustered relation still blocks a type/domain recreate), domain/domain-constraint/policy expression deps, and partition child→parent — every leg's refclassid filter also names `pg_ts_*` and `pg_op*` (`pg_operator`/`pg_opclass`/`pg_opfamily`), so dependents on managed text-search/operator objects record the edge too. A final union maps `pg_depend` rows whose `classid` names an unsupported object family (`pg_type` UDTs, `pg_language`, `pg_rewrite` rules, `pg_statistic_ext`, `pg_cast`, `pg_transform`, `pg_conversion`, `pg_operator`/`pg_opclass`/`pg_opfamily`, `pg_ts_*`) to edges `OTHER dependent → ref` (the operator/text-search families are managed now — their rows resolve refs *to* them so an OTHER dependent still blocks a drop), so an unrecreatable dependent blocks a drop/recreate with `PlanningException` per 5.8.3 (refs resolve via `byOid`/`conByOid`/`collByOid` and the `pg_ts_*` oid maps, so an OTHER dependent on a text-search object still blocks its drop). `loadExternalDependents` mirrors these for other-namespace dependents (5.8.3) — including legs for external objects that reference our managed text-search/operator objects (external views and column defaults, and the families' own cross-namespace members: `pg_ts_dict`→`pg_ts_template`, `pg_ts_config`→dict/parser — mappings record as config deps, `pg_opclass`/`pg_amop`/`pg_amproc`/`pg_operator`/`pg_opfamily` member refs), resolved via `byOid` without a target-side join.
- `PgCatalog` loaders skip non-standalone catalog rows: `loadConstraints` filters `conislocal = false` (partition-child and inheritance copies — including ATTACH-absorbed ones — which cannot be created or dropped directly; the parent's object covers them), `loadTriggers` filters `tgparentid <> 0` (partition clones; `tgisinternal` alone does not catch them), `loadIndexes` filters `pg_inherits` children (partition-child indexes). Rules and statistics do not clone to partitions. Columns on `PARTITION` children load as `COLUMN` objects parented on the `PARTITION` id, and on `inherited:` parents as before (`loadColumns` joins `relkind IN ('r','p')`); foreign-table (`f`) columns do not. Physical/planner properties that are not declarable schema shape stay out of every canonical definition by design (invisible drift is the documented boundary): `attstattarget` (planner hint), `relam` and `reltablespace` (cluster-level targets), `indisclustered` (transient) — index `TABLESPACE` is the exception, since `pg_get_indexdef` emits it into the deparsed definition. Column `attstorage`/`attcompression` *are* in the canonical: they are column storage parameters declarable in `CREATE TABLE` and reconcilable via `SET STORAGE`/`SET COMPRESSION`.
- `PgCatalog.loadOther` detects every namespace-scoped object the managed kinds don't claim (spec A.5): non-managed relations and inheritance children, base-type UDTs (a range's generated family — multirange type, constructor routines, the range→multirange cast — folds into the managed range `TYPE` via `loadAutoTypeFamily`/`loadRanges` and is never an object; every relation also maps its companion rowtype `pg_type` oid to its id so a column typed as the relation deps on it — OTHER rowtypes included, which keeps an `inherited:` child blocking a drop/recreate and keeps a cast on an unsupported rowtype `cast:` OTHER: a managed `CAST`/`TRANSFORM` requires *every* in-namespace anchor to resolve managed; aggregates are managed `AGGREGATE`s — `pg_get_functiondef` refuses them, so `loadAggregates` composes the canonical and `CREATE AGGREGATE` from the `pg_aggregate` option list; drift is `DROP`+`CREATE` `REBUILD`), unrecreatable collations, default conversions, comments on unmanaged targets, security labels on unmanaged targets, privileges on unmanaged targets (on managed rel/proc/type targets a non-null `relacl`/`proacl`/`typacl` becomes a managed `PRIVILEGES` object mirroring the target, and a column-level `attacl` becomes `PRIVILEGES <col>` parented on the relation — the canonical is the sorted `grantee:PRIVILEGE[*]` token list, `<owner>`-normalised, grantor dropped; `PgRender` diffs the tokens into `GRANT`/`REVOKE` (the column name parenthesized after the privilege word via `GRANT_COLUMN`), `REVOKE GRANT OPTION FOR` when the privilege itself stays, skipping `<owner>` implicit rights), default privileges (`pg_default_acl` rows scoped to the namespace become managed `DEFAULT_PRIVILEGES <CLASS> for <role>` — `GRANT_TARGET` carries the class word, `GRANT_PREFIX` the `ALTER DEFAULT PRIVILEGES FOR ROLE "r" IN SCHEMA ${namespace}` clause; global rows stay invisible), ownership of unmanaged targets (on managed rel/proc/type targets a non-session `relowner`/`proowner`/`typowner` becomes a managed `OWNERSHIP` object mirroring the target — index, toast, composite-class, rowtype and array-type owner rows are followers of their parent and skipped), and casts/transforms/languages anchored to a namespace object (a cast anchored to a managed type or cast function becomes a managed `CAST`, a transform on a managed `trftype` a managed `TRANSFORM` — `context/method/func` resp. from/to-SQL function canonicals, `DROP CAST`/`DROP TRANSFORM`+`CREATE` `REBUILD`; a language is cluster-level and stays `OTHER` always) — all `OTHER` → `UNSUPPORTED`, except that `privileges:*` carries the same token list plus `Dialect.CONTENT_COMPARED_ATTRIBUTE`, and `Differ` emits no difference when the target holds an equal object (spec 5.4); every other `OTHER` category is presence-only and is reported on every run. `pg_description`/`pg_seclabel` use `classoid` (not `classid`).
- Managed beyond the base kinds: `MATERIALIZED_VIEW` (canonical includes `relispopulated`; drift is DESTRUCTIVE `DROP`+`CREATE`+`REFRESH`), enum `TYPE` (ordered labels; pure in-order append renders `ALTER TYPE ... ADD VALUE`, removal/reorder stays manual), `DOMAIN` (base type, nullability, default, collation, named `CHECK`s; base-type change is manual, the rest rebuilds in place), `POLICY` (command/permissive/roles/exprs; drift is `DROP POLICY`+`CREATE POLICY`), `EXTENSION` (presence-only; `CREATE EXTENSION IF NOT EXISTS ... WITH SCHEMA`), `COMMENT` (target-mirroring id, comment text canonical, `dependsOn` the target; removing `COMMENT ON` reports UNEXPECTED, never drops). `relrowsecurity`/`relforcerowsecurity` live on the TABLE canonical — enabling RLS is the table's create, not a policy step. Text-search objects are managed as `TEXT_SEARCH_TEMPLATE`/`…PARSER`/`…DICTIONARY`/`…CONFIGURATION` — `loadTextSearch` composes canonical and `CREATE` from the catalog rows (no `pg_get_*def` exists, the AGGREGATE pattern); a configuration's `pg_ts_config_map` rows fold into it as `ALTER ... ADD MAPPING` fragments in `POST_SQL` (token aliases via `ts_token_type(cfgparser)`), never standalone objects; any drift is `DROP`+`CREATE` `REBUILD`, and dep edges record function/template/parser/dictionary references. Operators are managed as `OPERATOR` (id name `opname(leftarg,rightarg)`, `NONE` for an absent operand), `OPERATOR_FAMILY` and `OPERATOR_CLASS` (id names `name USING am`) — `loadOperators` composes canonical + `CREATE` from the catalog rows the same way; an operator class's `pg_amop`/`pg_amproc` members (left type = `opcintype`, cross-type included) fold into its canonical and render inside `CREATE OPERATOR CLASS … AS`, while standalone family members stay unmodeled and `ALTER OPERATOR FAMILY … ADD|DROP` remains rejected.
- `SchemaReconciler.dump()` (spec 3.1): steps 1–3 of 5.1 — connect, lock, `readSnapshot` — rendered by `DumpRenderer` as a desired-state script: header (dialect id, quoted namespace, fingerprint; no timestamp), each object in `dependsOn` order as `Dialect.dumpStatements` fragments terminated by `;`, empty fragments as `-- folded:`/`-- unsupported:` comments. `desiredState` is optional on the Builder — required only for `plan()`/`reconcile()`/`apply()`. PG fills `PgCatalog.DUMP_SQL` per object: a table's fragments mirror `createTableStatements` (owned sequences, folded columns, replident/RLS alters); a sequence owned by a snapshot table gets no fragment of its own; fragments keep `${namespace}` tokens and join with `\0` (impossible in PG text); trailing `;` deparsed artifacts (`pg_get_viewdef`) are stripped at emit.
